Claude Code CLI、Desktop和安卓app遥测行为分析

完整分析报告：GitHub
一、核心结论
作者分析了 Claude Android、Claude Code CLI 和 Claude Desktop 三种客户端的遥测行为。
主要发现：
1. Android App 可能上传稳定设备标识、真实 IPv6 地址、SIM 卡国家代码和运营商信息。
2. Claude Code CLI 在使用第三方 API 时，可能向 Anthropic 上传自定义 API 地址，并关联本地设备标识。
3. Claude Desktop 可能上传第三方 API 域名、时区、系统语言、硬件配置和安装标识。
4. 即使使用代理，某些设备和系统信息也可能通过遥测暴露。
5. 这些数据可能被用于设备关联、环境识别和风险评估，被 Anthropic 用于封号。
二、各客户端总结：
【Claude Android App】
- Android ID
- 真实 IPv6 地址
- SIM 卡国家代码
- 当前网络运营商
【Claude Code CLI】
- 第三方 API 地址可能被上传。
- 上传信息可能关联 device_id。
- 使用本地代理可能改变上报的 API 地址。
- 可以尝试通过环境变量限制非必要遥测。
【Claude Desktop（macOS）】
- 第三方 API 域名
- ant-did 安装标识
- 系统时区
- 系统语言
- 硬件与设备环境
- Sentry 相关遥测
三、潜在隐私风险
1. 代理不等于完全隐藏设备信息
代理通常主要影响网络请求的出口路径。但是，客户端仍然可能主动读取并上传：
- 本地网络接口地址
- 设备标识
- SIM 卡信息
- 系统语言
- 时区
- 硬件配置
因此，仅仅更换代理节点并不能保证隐藏全部真实环境信息。
2. 更换账号不等于更换设备
如果客户端存在相对稳定的设备标识，那么不同账号的使用行为在技术上可能被关联。
但是否实际进行跨账号关联，仍取决于服务端的处理方式。
3. 使用第三方 API 不等于完全脱离官方遥测
即使模型请求走第三方 API，部分遥测请求仍可能发送到 Anthropic 或第三方监控服务。
所以，需要区分：模型 API 请求地址与客户端遥测接收地址，两者不一定相同。
4. 系统环境可能形成设备特征
例如：
系统时区：Asia/Shanghai
系统语言：zh_CN
设备型号：MacBook
API 地址：某第三方中转服务
安装标识：固定 ant-did
这些信息组合后，可能被用于判断设备环境或关联使用行为。
